# 自動化測試的專家建議指南：平衡人類工程師與 AI Agent 的力量

## 序言：兩種自動化的思維範式
在現代軟體開發中，自動化測試正處於一個轉型期。我們不再只討論「如何寫腳本」，而是在討論「誰來執行測試」。本文將深入探討兩種截然不同的自動化思維模式：**人類工程師模式 (Human-Centric)** 與 **AI Agent 模式 (AI-Centric)**。

## 篇章一：Playwright Codegen —— 建立穩固的測試基石
對於需要長期維護、整合進 CI/CD 流程的專案，使用 Playwright 官方提供的錄製器是建立「回歸測試 (Regression Testing)」最穩固的方法。

### 1. 核心技術與方法
* **直接使用命令列啟動錄製**
  透過指令 `npx playwright codegen` 可以開啟一個特殊的 Chrome 視窗與 Playwright Inspector，您的每一次點擊都會即時轉化為程式碼。
* **自動化輸出至實體檔案**
  利用 `-o` (Output) 參數，可以跳過複製貼上的步驟，直接將腳本存入專案路徑：
  ```bash
  # 產出 TypeScript 測試檔
  npx playwright codegen -o tests/my-test-spec.ts
  ```
* **登入狀態的持久化 (Session Persistence)**
  針對需要登入流程的複雜測試，利用 `storageState` 可以大幅節省時間：
  1. **儲存狀態**：`npx playwright codegen --save-storage=auth.json` (完成登入後關閉)。
  2. **載入狀態**：`npx playwright codegen --load-storage=auth.json wikipedia.org`。

### 2. 高效率整合：VS Code 擴充功能
如果您使用 VS Code，安裝 `Playwright Test for VS Code` 後，透過 Testing Panel 的 "Record new" 功能，錄製結果會直接寫入編輯中的檔案，體驗極其流暢。

💡 **專家提示**：生成的程式碼常依賴文字定位 (e.g., `getByRole('button', { name: '送出' })`)。若網頁版面改版，建議人工檢查並將重要元素改用 `data-testid` 定位以增加穩定度。

## 篇章二：OpenCode + playwright-cli —— 開啟 AI 自動化新紀元
當我們使用 OpenCode CLI 操作 `playwright-cli` 時，我們是在指導一個 **AI Agent** 進行探索。

### 1. 運作機制解析
* **元素簡化 (Snapshotting)**：為了節省 Token 並降低 AI 的理解成本，`play於playwright-cli` 會將網頁 HTML 簡化為 YAML 格式的「快照」，並利用 Accessibility Tree 將按鈕編號（例如 `e15`, `e3`）。
* **AI 指令驅動**：操作者不再是點擊畫面，而是透過文字指令 (例如 `click e15`) 來引導 AI。

### 核心挑戰
* **Token 成本**：每次重新探索都需要消耗 Token 來讀取與解析網頁結構。
* **元素漂移 (Element Drift)**：只要網頁結構稍有變動，原本的 `e15` 可能會變成 `e16`，導致 AI 執行錯誤，必須依賴 AI 重新推理。

## 篇章三：深度對比 —— 您該如何選擇？

| 特性 | Playwright Codegen (人類模式) | OpenCode + playwright-cli (AI 模式) |
| :--- | :--- | :--- |
| **操作主角** | 人類工程師 (點擊瀏覽器) | AI Agent (理解指令與快照) |
| **產出物** | 標準測試腳本 (`.spec.ts`, `.py`) | YAML 快照與指令紀錄 |
| **定位機制** | 語義化定位器 (Role, Text, etc.) | 虛擬標籤編號 (e1, e2...) |
| **重現穩定度** | 極高，適合 CI/CD 迴歸測試 | 中等，受網頁動態結構影響 |
| **成本結構** | 低 (僅消耗運算資源) | 高 (涉及 AI 推理與 Token 費用) |

## 總結：最佳實踐建議 (Strategic Roadmap)

* **如果您要建立「穩固的自動化測試套件」**：
  請選擇 **Play於Playwright Codegen**。將錄製好的 `.spec.ts` 存入 Git，這是最快、最省錢且符合業界標準的 QA 做法。
* **如果您要進行「快速的功能探索或自動生成腳本」**：
  請利用 **OpenCode + Playwright Generator Agent**。您可以下指令：「幫我用 Playwright Generator Agent 去探索這個網頁，並在 `tests/` 下生成一個可以重複執行的測試檔。」

透過這種方式，您能結合 AI 的「自動化編寫能力」與 Codegen 的「穩固執行特性」，建立出一套強大的自動化測試生態系。
