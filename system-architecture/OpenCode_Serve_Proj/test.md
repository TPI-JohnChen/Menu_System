# OpenCode Chat — 功能測試案例 (test.md)

> 測試對象:`index.html` + `start.ps1`。
> 前置條件:已啟動 `opencode serve`(預設 `http://127.0.0.1:4096`),並以靜態伺服器服務頁面。
> 快速手動環境:`opencode serve --port 4096` + `python -m http.server 8000 --bind 127.0.0.1`,開 `http://127.0.0.1:8000/index.html`。

---

## TC-01 頁面載入與預熱
| 項目 | 內容 |
|------|------|
| 前置 | serve 已啟動 |
| 步驟 | 開啟 `http://127.0.0.1:8000/index.html` |
| 預期 | 標題「OpenCode Chat」;分頁依 `projects` 數建立;`#nowdir` 顯示第一個專案目錄;log 出現各專案「SSE 已連線」;狀態列「已連線(預熱)」(綠) |

## TC-02 專案分頁切換
| 項目 | 內容 |
|------|------|
| 前置 | TC-01 |
| 步驟 | 點第二個分頁 |
| 預期 | `#nowdir` 切為第二個專案目錄;`#messages` 顯示該專案內容;狀態/傳送鈕反映該專案狀態 |

## TC-03 模型清單載入
| 項目 | 內容 |
|------|------|
| 前置 | serve 正常 |
| 步驟 | 檢查「模型」下拉 |
| 預期 | 第一個選項「預設模型」,其後列出 `provider · 模型名`(值為 `providerID/modelID`),數量與 `/config/providers` 一致(實測約 90 項) |

## TC-04 送出對話並收到回覆
| 項目 | 內容 |
|------|------|
| 前置 | 任一分頁已連線 |
| 步驟 | 輸入「請只回覆:OK」按 Enter(或點「傳送」) |
| 預期 | 輸入框清空;出現「你」氣泡;狀態列變「執行中…」、傳送鈕停用;assistant 氣泡**逐字串流**長出內容;結束後 meta 顯示「模型 … · TTFT … · 完成 …」;狀態列回到「待命」 |

## TC-05 Shift+Enter 換行不送出
| 項目 | 內容 |
|------|------|
| 步驟 | 輸入「第一行」按 Shift+Enter 再輸入「第二行」 |
| 預期 | 不送出,輸入框內換行;再按 Enter 才送出(可含換行) |

## TC-06 Markdown 渲染
| 項目 | 內容 |
|------|------|
| 步驟 | 請模型回覆含表格、標題、程式碼區塊、清單、粗體、連結的內容;或直接檢視已知含表格之歷史訊息 |
| 預期 | 表格/標題/``` 程式碼區塊/清單/粗體/超連結皆正確渲染;tool part 顯示「[工具] … (completed)」並可展開輸出;file part 為可開新分頁連結 |

## TC-07 中斷(執行中)
| 項目 | 內容 |
|------|------|
| 前置 | 送出後 busy(狀態列「執行中…」) |
| 步驟 | 點「中斷」 |
| 預期 | 送出 abort(HTTP 200);log 出現「<label>: 已送出中斷」;狀態列回「待命」、傳送鈕恢復 |

## TC-08 中斷(閒置時不洗版)
| 項目 | 內容 |
|------|------|
| 前置 | 未執行任何任務(busy=false) |
| 步驟 | **連續快速**點「中斷」10 次以上 |
| 預期 | log **不新增**任何一行;按鈕短暫閃示「無任務可中斷」並還原;介面不被擋住 |

## TC-09 日誌面板防爆
| 項目 | 內容 |
|------|------|
| 步驟 | 短時間內重複觸發相同 log(如同樣權限請求);製造超過 60 條 log |
| 預期 | 相同文字 2.5 秒內只記一條;總數上限 60 條、超過丟最舊;面板高度固定(約 4 行)可捲動,不遮蔽聊天區 |

## TC-10 新對話
| 項目 | 內容 |
|------|------|
| 前置 | 該分頁非 busy |
| 步驟 | 點「新對話」 |
| 預期 | 建立新 session;該分頁訊息清空(顯示「尚未有訊息」佔位);模型指定與已放行權限重設;log 記錄新 session id |

## TC-11 新對話(執行中阻擋)
| 項目 | 內容 |
|------|------|
| 前置 | 該分頁 busy |
| 步驟 | 點「新對話」 |
| 預期 | 不建立;log 提示「正在執行,請先中斷再開新對話」 |

## TC-12 指定模型送出
| 項目 | 內容 |
|------|------|
| 前置 | 模型清單已載入 |
| 步驟 | 選取 `opencode/deepseek-v4-flash-free` 等可連線模型 → 送出訊息 |
| 預期 | 回覆 meta 的「模型」即為所選 modelID(實測:`deepseek-v4-flash-free` 對應) |
| 注意 | **LM Studio 模型(localhost:1234)未啟動時選用會卡住**;請改用可連線的 provider(如 opencode 免費模型) |

## TC-13 權限自動放行
| 項目 | 內容 |
|------|------|
| 前置 | `autoAllowOnce=true` |
| 步驟 | 送出會觸發工具(如 git 操作)的指令,觀察 log |
| 預期 | 工具執行不需手動確認;log 出現「[權限請求] bash …」與「已回覆 once」;請求由輪詢(`GET /permission`)兜底處理,同 request 不重複回覆 |

## TC-14 舊 session 串流不混入
| 項目 | 內容 |
|------|------|
| 前置 | 執行過 TC-10(有舊 session) |
| 步驟 | 開新對話後再送出 |
| 預期 | 舊 session 的事件不會污染目前訊息畫面(handleEvent 依 sessionID 過濾) |

## TC-15 後端暫時不可用時之韌性
| 項目 | 內容 |
|------|------|
| 前置 | 頁面已開啟 |
| 步驟 | 先關閉 serve,載入頁面,再開啟 serve |
| 預期 | `loadModels` 自動重試(5 次 × 1.5s),serve 恢復後模型清單自動出現;SSE 自動重連後狀態回「已連線(預熱)」 |
## TC-16 靜態伺服器啟動(啟動腳本)
| 項目 | 內容 |
|------|------|
| 前置 | port 8000 未被佔用 |
| 步驟 | 執行 `start.ps1` |
| 預期 | 自動啟動 serve(4096)、綁定 `127.0.0.1:8000`、預熱專案、開啟 `http://127.0.0.1:8000/index.html`;8000 起不來時會印出明確錯誤與釋放 port 指令 |

## TC-17 動態加入專案(UI)
| 項目 | 內容 |
|------|------|
| 前置 | 頁面已開啟(2 個預設分頁) |
| 步驟 | 點 header「＋ 專案」→ 目錄欄輸入 `C:\D\git-Hub-public\opencode`、名稱留空 → 按「加入」(或 Enter) |
| 預期 | 表單收合;出現第 3 個分頁(名稱取目錄 basename = `opencode`);自動切為 active(`#nowdir` 顯示該目錄);log 出現「已加入專案 …」並連上「SSE 已連線」;`localStorage` 已存該專案 |

## TC-18 動態加入之重複與空白
| 項目 | 內容 |
|------|------|
| 步驟 | (a) 目錄空白按「加入」;(b) 再加入與預設(或已加)相同的目錄 |
| 預期 | (a) log 提示「請輸入專案目錄路徑」、不建立;(b) log 提示「…已存在,未重複加入」、分頁數不增加 |

## TC-19 動態專案持久化(重載)
| 項目 | 內容 |
|------|------|
| 前置 | 已新增一動態專案 |
| 步驟 | 重新載入頁面(或關閉重開) |
| 預期 | 動態專案分頁自動重現(`localStorage` 回放),且不搶佔 active(仍為第一個預設專案);可在該專案正常送出並收到回覆 |

## 已通過之自動化驗證(供參考)
- **單元 harness(jsdom 取代,Node 直跑)**:19 項全 PASS,含動態加入(dedup/tab/目錄名/persist/noSwitch)、idle 中斷不寫 log、send 帶 model。
- **瀏覽器 E2E(Edge headless + CDP 實跑)**:模型清單 90 項;「＋專案」表單展開 → 加入動態專案 → 第 3 分頁出現/切成 active/SSE 連線/`localStorage` 持久化 → 重載後仍重現 → 於該專案送出收到回覆「OK」;全程無 console 例外。
- **後端驗證**:`/config/providers`、`/session` 回 200;CORS 回應 `Access-Control-Allow-Origin: <origin>` 正常。
